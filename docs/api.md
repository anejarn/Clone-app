# API

Sigma's JSON API over HTTP, served by Next.js Route Handlers in `app/api/`. Business rules live in `lib/server/*`; routes only parse input, check the session and map errors.

- **Errors**: `{ "error": { "code": "UNAVAILABLE", "message": "Ces dates ne sont plus disponibles." } }` with a matching status (400 invalid input, 401 signed out, 403 forbidden, 404 not found, 409 conflict, 413 body too large, 422 rule violated). Messages are French and safe to show.
- **Input limits** (`lib/server/http.ts`, `lib/server/schemas.ts`), on every route including `/api/auth/*`: request bodies are read as a stream and refused past 64 KB with `413 PAYLOAD_TOO_LARGE`; free text (search query, place, review body, account name) with a control character other than tab or line break is `400 INVALID_INPUT`; an id that isn't 1–64 characters of `A-Z a-z 0-9 _ -` is answered `404 NOT_FOUND` without a database query (`DELETE /api/wishlist/:id` answers `204`, as for any id not saved; in a body it is `400 INVALID_INPUT`).
- **Auth**: session cookie set by Better Auth (`/api/auth/*`). Writes also require a same-origin `Origin` header when one is sent (browsers always send it).
- **Dates**: `yyyy-MM-dd`, checkout exclusive. Money: integer centimes of dirham (MAD).
- **Drafts**: only published listings exist for the public routes (search, detail, availability, quote, booking, favourites); a draft answers `404` like an unknown id.

## Booking rules

- Stays start today or later (today = the listing's local date, from `Place.timezone`), at most 365 days ahead, and last 1–60 nights; cancellation closes on the listing's local arrival day.
- `adults + children ≤ maxGuests`; at least one adult; pets need the "Animaux acceptés" amenity.
- Price is computed on the server by the pricing engine (`lib/pricing/engine.ts`): Σ of the nights' prices (base price, or the season's or event's) + cleaning, stored on the booking with `nightlyCents` = the average of the nights and `totalCents` exact (`serviceFeeCents` stays in the response and is 0: Sigma charges guests no service fee).
- Minimum stay: the listing's `minNights`, raised by any season or event of the listing covering one of the stay's nights; the search applies the same rule.
- **No double booking**: checked in the transaction, and guaranteed by the Postgres exclusion constraint `bookings_no_overlap` (GiST on listing + `daterange`, confirmed stays only). Concurrent requests for the same dates: exactly one succeeds (see `tests/integration/bookings.test.ts`).
- Guests cancel their own confirmed stays until the day before arrival; cancelled dates become bookable again.

## Finances (Lot 6a)

Server actions in `app/admin/finances/actions.ts`, each guarded by `requireAdminAction("/admin/finances")` (ADMIN with double authentification) and answering `{ error }` / `{ message }` (forms also `fieldErrors`, `values`); another organization's booking, home or expense is « introuvable ». Amounts typed in dirhams, stored in centimes.

- Expenses: `createExpenseAction` (`listingId`, `date` yyyy-MM-dd ≤ today, `category` REPAIR/PURCHASE/SUPPLIES/CLEANING/UTILITIES/OTHER, `description`, `supplier`, `amount` TTC, `paidBy` SIGMA/OWNER, `rebillToOwner`, `ticketId`, optional `receipt` file) → draft and its `id`; `updateExpenseAction(id)`, `deleteExpenseAction(id)` (drafts only); `uploadReceiptAction(id)` (a draft's, or a validated expense without one); `validateExpenseAction(id)` (posts to the journal, freezes); `reverseExpenseAction(id, reason)` (opposite entry, REVERSED).
- A booking's split: `setSplitInputsAction(bookingId)` (`gross`, `platformFee`, `fxRate` MAD per unit, `note`; empty = none), `reapplyTermsAction(bookingId)`.
- Months: `closeMonthAction(yyyy-MM)` (past months only; posts the sublease rents), `reopenMonthAction(month, reason)`; `addAdjustmentAction` (`listingId`, open `month`, `direction` credit/debit, `amount`, `reason`).
- Settings: `saveFinanceSettingsAction` (`cleaningBeneficiary`, `commissionBase`, `allocation`, `fee_<PLATFORM>` in %), `saveListingTermsAction(listingId)` (`cleaningFeeBeneficiary`, `subleaseRent`, `subleaseRentFrom`).

## Owner statements and portal (Lot 6b)

Server actions in `app/admin/finances/actions.ts` (ADMIN with double authentification, as above):

- `closeMonthAction(month)` now also generates the month's owner statements (a failure there leaves the month closed: generate again).
- `generateStatementsAction(month)` (closed months: a new version only for owners whose figures changed), `regenerateStatementAction(ownerId, month)` (always a new version; the old ones stay).
- `recordPayoutAction(ownerId, month)` (`paidOn` yyyy-MM-dd ≤ today and ≥ the month's first day, `reference` 2–100 characters, `amount` in dirhams; needs the month's statement) posts an `OWNER_PAYOUT` entry in the month of its date (or the next open month); `reversePayoutAction(id, reason)`.
- `saveBrandingAction` (`legalName`, `legalAddress`, `ice` 15 digits or empty, `rcNumber`, `taxIdNumber`, `eurRate` MAD per euro or empty, `logo` PNG/JPEG ≤ 1 MB, `removeLogo`).

Owner documents, in `app/admin/utilisateurs/actions.ts` (ADMIN): `addOwnerDocumentAction(ownerId)` (`kind` MANDATE/CONTRACT/LICENSE/INSURANCE/OTHER, `title`, optional `listingId` of that owner, `file` PDF/JPEG/PNG/WebP ≤ 5 MB), `deleteOwnerDocumentAction(id)`.

Routes (never cached; anything not allowed is the same `404`, so an answer never tells whether a statement or document exists):

- `GET /api/finances/statements/<id>[?telecharger=1]` → a stored statement (PDF) for the associés of its organization and its own owner.
- `GET /api/admin/finances/statements/apercu?mois=yyyy-MM&proprietaire=<id>` → the statement as it would be now, « Provisoire » while the month is open (ADMIN).
- `GET /api/admin/finances/statements/mois?mois=yyyy-MM` → every owner's latest statement of the month in one PDF (ADMIN).
- `GET /api/owner-documents/<id>` → a document shared with an owner, for the associés and that owner.
- `GET /api/finances/expenses/<id>/receipt` → also for the home's owner once the expense is validated (Lot 6a).
- `GET /proprietaire/langue?l=fr|ar|en&retour=/proprietaire/…` → keeps the portal's language in the cookie `sigma_owner_lang`, then 303 to the portal page.
