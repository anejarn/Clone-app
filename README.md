# Nidou: ski apartments in Orcières-Merlette 1850 and Les Orres

Nidou is a short-stay marketplace for the empty ("cold bed") ski apartments of two mid-size Hautes-Alpes resorts, **Orcières-Merlette 1850** and **Les Orres**, launching for the February 2027 school holidays. It started as a replica of [airbnb.fr](https://www.airbnb.fr/) (own brand, font and imagery) and keeps its look and design tokens.

- **Guests** book homes (apartments, studios, chalets) for 2 nights or more (some homes ask 3), arriving any day. Prices are all-in: no service fee, the taxe de séjour is included and shown as its own line.
- **Owners** pay a 10 % commission (12 % with VAT) on nights + cleaning; founding hosts (owners who open at least four winter weeks before 15 December 2026) pay 5 % on stays checking in by 30 April 2027. Nidou collects the taxe de séjour for the commune and exports each home's bookings as an iCal feed.
- Listings show the legal mentions: registration number, "meublé de tourisme" classification (or "non classé") and DPE class.

Product rules and data: [`docs/api.md`](docs/api.md) (API and booking rules), [`docs/architecture.md`](docs/architecture.md). The original replica's recon and design system: [`docs/recon/airbnb-fr.md`](docs/recon/airbnb-fr.md), [`docs/design-system.md`](docs/design-system.md).

## Pages

| Page | What it does |
|---|---|
| `/` | Promise, the two resorts, rows per resort, "Ski aux pieds" and "Grands logements pour les familles", searches by resort (studios, apartments, chalets, ski aux pieds…), owner call-out |
| `/s/<resort>/homes` | Results with availability, guests/pets, `type` and `ski` filters and pagination; cards show classification, lift distance and, with dates, the all-in total for the searched adults |
| `/rooms/<id>` | Listing: photos, facts (guests, rooms, lift distance, resort altitude), classification, registration number, DPE, amenities, reviews, host, location; booking card with calendar (booked nights and minimum stay enforced), guests within capacity, live price breakdown, "Réserver" (signed out: login and back) |
| `/devenir-hote` | Owner offer, what Nidou handles, lead form (`POST /api/host-leads`) |
| `/trips`, `/wishlists`, `/login` | Stays with their taxe de séjour and cancellation, favourites, email + password accounts |

`/experiences`, `/services` and `/homes` redirect permanently to `/`.

## Deferred

Not built yet, on purpose: **payments** (Stripe Connect: guest charge, owner payouts, the commission and its VAT are only stored on each booking), **verified host onboarding** (owners leave a lead; listings are seeded), **iCal import** (only export), the **taxe de séjour remittance file** for the communes, **DAC7 and "API meublés" exports**, **damage cover**, and **guest–host messaging**.

Photos are random placeholders from picsum.photos; hosts, listings and reviews are generated by `prisma/fixtures.ts`.

## Develop

Needs Node 22.18+, pnpm and Postgres 16.

```bash
cp .env.example .env          # then set BETTER_AUTH_SECRET (openssl rand -base64 32)
docker compose up -d          # Postgres with `nidou` and `nidou_test` databases
pnpm install                  # also generates the Prisma client
pnpm db:deploy && pnpm db:seed
pnpm dev                      # http://localhost:3000
```

| Command | What it does |
|---|---|
| `pnpm lint` / `pnpm typecheck` | ESLint, and route-type generation + `tsc` |
| `pnpm test` | Unit tests (`tests/unit`), no database; date tests also run under UTC+14 and UTC−8 |
| `pnpm test:integration` | Server logic against `nidou_test` (`tests/integration`): migrates and reseeds it first |
| `DATABASE_URL=<test db> pnpm build && pnpm test:e2e` | Playwright against the production build and `nidou_test`: user journeys (search, listing page, booking, owner form), API contract, security, accessibility (axe), keyboard, timezones, design conformance; desktop and mobile |
| `pnpm test:coverage` | Unit + integration coverage of `lib/` |
| `pnpm db:migrate` | Create/apply a migration after editing `prisma/schema.prisma` |
| `pnpm db:seed` | Reload demo data (clears places, listings, bookings, reviews and favourites; keeps real accounts and owner leads) |
| `pnpm db:reset` | Drop and recreate the database, then seed. Destructive, dev only |

Demo hosts and guests (`@demo.nidou.fr`) have no password; create an account at `/login`.

## Backend at a glance

- **Data**: Postgres via Prisma 7 (`prisma-client` generator + `@prisma/adapter-pg`). Schema in `prisma/schema.prisma`; integrity rules Prisma can't express (no overlapping stays, value checks) are hand-written in the migrations (`bookings_no_overlap`, the price-snapshot and listing checks of `ski_pivot`). A database migrated from before `ski_pivot` must be reseeded right after `prisma migrate deploy`: its old places and listings have no INSEE code or registration number and can't be updated or quoted (see `docs/architecture.md`).
- **Pricing**: `lib/pricing.ts` (guest total, commission, VAT, owner payout) and `lib/tourist-tax.ts` (the communes' grids with their sources), pure and shared by the booking card and the server.
- **Server code**: `lib/server/` (`catalog`, `bookings`, `host-leads`, `wishlist`, `reviews`, `auth`), plain async functions that tests call directly. Pages use the cached wrappers in `lib/data/repo.ts` (`"use cache"`, tag `listings`): the homepage and every `/rooms/<id>` are prerendered; availability, prices and the session are fetched live by the booking card.
- **Auth**: [Better Auth](https://www.better-auth.com) with email + password and the Prisma adapter, chosen over Auth.js v5 (still in beta; its maintainers moved to Better Auth).
- **API**: `app/api/*`, documented in [`docs/api.md`](docs/api.md).
- **QA**: findings, fixes, Lighthouse and parity results in [`docs/qa-report.md`](docs/qa-report.md).

Next.js 16 runs with Cache Components: data functions use `"use cache"` + `cacheLife`, and anything that reads request data (params, search params, cookies) must sit inside `<Suspense>`. See `AGENTS.md` and the docs bundled in `node_modules/next/dist/docs/`.
